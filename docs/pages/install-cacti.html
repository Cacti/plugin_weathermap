Installing with Cacti

Install this plugin inside an existing Cacti installation. Follow the requirements of that Cacti release as well as the plugin requirements below.

Requirements

  • Cacti 1.2.29 or later, as declared in the plugin's INFO file.
  • A PHP version and extensions compatible with your Cacti release. GD must support the image formats you use; FreeType is needed for TrueType labels and curved comments. Enable PHP intl for the renderer’s locale-aware timestamp formatting.
  • A working Cacti poller and configured RRDtool executable for RRD-based maps.
  • Filesystem permissions for configuration saves, generated output and optional image uploads. The web and poller service accounts may differ.

Do not follow the old PHP 4, Cacti 0.8.x or separate Plugin Architecture instructions. Do not install PEAR solely on the assumption that the integrated editor requires it; the legacy command-line wrapper has its own dependencies.

Install and enable

  1. Back up an existing plugin before replacing files; use the upgrade checklist for existing installations.
  2. Download the desired release from the official releases. Place its contents under <cacti_root>/plugins/weathermap/. GitHub archives can have a versioned top-level directory: rename that directory to weathermap. Verify that INFO and setup.php sit directly inside it, not in a nested folder.
  3. Configure the permissions described below.
  4. In Cacti Plugin Management, install and enable Weathermap. Database setup/upgrades are handled by the plugin.
  5. Grant the necessary view/manage permissions through Cacti User Management or User Groups. Review per-map permissions too.
  6. Create a small map, register it in management if needed, and confirm rendering during a normal poller cycle.

Filesystem permissions

Identify the actual PHP web account and poller account first. Use ownership, a dedicated shared group or ACLs appropriate to your system; avoid blanket chmod 777 instructions.

Location Access needed
configs/ and files Web account needs read/write for editing and permission to create replacement files in the destination directory. Poller needs read access. Included files require their own appropriate permissions.
output/ Poller needs write access for rendered maps and thumbnails; the web server needs access to serve them.
images/objects/ and images/backgrounds/ Web account needs write access for uploads/deletion; renderer needs read access.
PHP service temporary directory Private history storage must be writable by the web account. It must not be published by the web server.
Fonts and RRD files Rendering account needs read access; RRDtool and any selected data-source tools must be executable.

SELinux/AppArmor policy and filesystem mount options may also affect writes. Check them if ownership looks correct but saves fail. Preserve the application's web-server protections; do not publish backup archives or configuration copies.

The bundle includes .htaccess restrictions in private directories such as configs/ and lib/. Apache must be configured to honour those files; other web servers need equivalent rules. Check a known private file URL, not just a directory listing: it should be denied rather than reveal its contents. Keep the documentation, viewer and image endpoints available as intended.

Verify installation

Check both the web PHP and CLI PHP environments: they may use different configuration files and extensions. Validate GD/FreeType and RRDtool availability through your normal Cacti/PHP diagnostics. The bundled legacy check.php is a supplemental diagnostic, not proof that every modern requirement is satisfied, and its output includes server details.

In the editor, save a node and reopen it. In the viewer, confirm the generated map and timestamp. Assign a traffic interface and verify the graph, direction and capacity. Review WEATHERMAP messages in Cacti's log. A saved configuration is not proof that the poller can render it.
